# Бриф проекта: AI-помощник для участия в тендерах

Для передачи в новый чат/Claude Code. Полная стратегия — в `niche_saas_strategy_v3.docx`, весь код — в этой же папке. Это краткая выжимка, чтобы не пересказывать всё заново.

## Идея одной строкой

SaaS-помощник для МСП, которые участвуют в тендерах и закупках **только как поставщики** (44-ФЗ/223-ФЗ) — не для закупочных отделов заказчиков.

## Почему эта ниша

- Рынок: закупки только у субъектов МСП — 9,55 трлн ₽ в 2025.
- Существующие игроки закрывают только часть: Тендерплан/Контур.Закупки — в основном поиск; DocSpace — для закупочных отделов заказчиков; Semantor/Litender — узкие AI-функции. Свободна связка «AI разбирает документацию → готовит заявку → проверяет на риск отклонения» именно для стороны поставщика.
- Готовый первый клиент: производственная компания отца (Квалитетпром) сама участвует в тендерах как поставщик.

## Что подтвердило первичное интервью (мама/бухгалтер Квалитетпрома)

- Компания — только поставщик, закупки сама не организует (подтверждает выбор ниши).
- Тендерами занимается бухгалтер, а не выделенный специалист — это довесок к основной работе. **Персона продукта шире, чем "тендерный специалист"** — это любой сотрудник МСП без профильной экспертизы.
- На один тендер уходит около целого рабочего дня: поиск на агрегаторе с готовыми фильтрами → ручной просмотр каждого тендера → проверка надёжности заказчика и соответствия компании требованиям.
- Решено не собирать доп. интервью у других поставщиков — одного достаточно, дальше проверяем на пилоте.

## Продукт: 5 модулей

1. **Радар тендеров** — AI-фильтрация потока извещений + проверка надёжности заказчика.
2. **Экстрактор требований** — AI разбирает документацию закупки в структурированный чек-лист.
3. **Линтер заявки** — проверка на частые формальные причины отклонения (44-ФЗ).
4. **Калькулятор цены и рисков** — антидемпинг (ст. 37 44-ФЗ), обеспечение, маржа.
5. **Пост-контрактный трекер** — сроки поставки, акты, банковские гарантии.

Базовое ядро (общее для всех): модули 1–3 + интеграция с ЕИС и топ-площадками.
Настраиваемый слой (под клиента): номенклатура ОКПД2, интеграция с 1С клиента, брендинг, workflow согласования.

## Технический стек

- Данные тендеров: официальный SOAP-сервис ЕИС (`zakupki.gov.ru`), с 1 июля 2025 FTP закрыт, только через токен.
- AI: YandexGPT и/или GigaChat — приоритет из-за требований 152-ФЗ (хранение данных россиян только в РФ с 1 июля 2025).
- Архитектура: парсинг документов — отдельный сервис; AI-слой — дешёвая модель для рутины + мощная для сложной документации.

## Немедленные следующие шаги (в новом чате/Claude Code, где есть доступ в интернет)

1. Получить токен ЕИС: `zakupki.gov.ru/pmd/auth/welcome` → Госуслуги → «Регистрация нового потребителя машиночитаемых данных» → физлицо/ИП. Бесплатно, 5 минут.
2. Вставить токен в `eis_client.py`, уточнить код региона (ORG_REGION — тот, что в файле, это только пример), запустить и проверить, что архив реально скачивается.
3. Получить ключ YandexGPT (Yandex Cloud) и/или GigaChat (developers.sber.ru), прогнать `yandexgpt_client.py`/`gigachat_client.py` — убедиться, что реальный вызов работает.
4. Взять у мамы 2–3 реальных документа по тендеру, прогнать через `requirement_extractor.py` с реальной моделью вместо мока (заменить `call_llm=_mock_llm` на `call_llm=call_yandexgpt`/`call_gigachat` — см. комментарий внизу `pipeline.py`) и оценить качество извлечения.
5. По плану на первый месяц дальше: донастройка под номенклатуру Квалитетпрома → условия пилота → go/no-go по MVP.
